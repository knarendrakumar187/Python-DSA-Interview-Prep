# Software Engineering 01 — Interview Short Notes

## What is SE?
Process to design, build, test, and maintain software as a team.

## SDLC stages (simple)
Requirement → Design → Develop → Test → Deploy → Maintain

## Models (know differences)
| Model | Idea | When |
|-------|------|------|
| Waterfall | one-way stages | clear fixed requirements |
| Iterative/Spiral | repeat + risk focus | evolving/risky projects |
| Agile | small sprints, feedback | most product teams today |
| RAD | fast prototypes | quick UI-heavy apps |

## Agile (say this)
> Work in short sprints, deliver working software often, take feedback, adapt.

## Coupling vs Cohesion
- **High cohesion** = module does one clear job (good)
- **Low coupling** = modules less dependent (good)

## Testing
- **Black box:** test without seeing code (input/output)
- **White box:** test with code knowledge (branches/paths)
- **Unit / Integration / System** testing levels

## SRS
Software Requirement Specification — clear document of what software should do.

## Speak answer
> I understand SDLC and prefer Agile for product work because requirements change. Good design keeps high cohesion and low coupling. Testing should include unit and integration checks before release.
